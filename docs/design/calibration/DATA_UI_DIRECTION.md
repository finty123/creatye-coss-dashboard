# Data UI Direction

The primary operational data language is:

```text
Modern operational cards + organized list blocks
```

Dense tables are not the primary visual language.

## Primary use cases

Use card/list-first patterns for:

- Pages.
- Automations.
- Publishing.
- Content Library.
- Activity.

## Why cards/lists

Cards and organized list blocks better support:

- Status-rich objects.
- Social/content context.
- Quick actions.
- Mixed media and metadata.
- Mobile/Web consistency.
- Operational scanning.

## When tables are allowed

Tables may exist when they materially improve:

- Comparison.
- Bulk management.
- High-density analysis.
- Sorting across many similar rows.

## Current Creatye continuity

Existing Mobile history/activity cards are valid conceptual references.

Future UI should refine them with:

- Better hierarchy.
- Clearer status.
- Improved spacing.
- More polished controls.
- Better selected/active states.
