# Visual Direction

## Visual personality

Creatye Studio should feel professional, modern, premium, creator-friendly, operational, clear, simple, intuitive, and fast.

It should feel like an evolved, premium version of the current Creatye Studio rather than a new product unrelated to the existing journey.

## Current Creatye preservation

Preserve conceptually:

```text
SELECT -> CUSTOMIZE -> PUBLISH
```

Preserve successful interaction principles:

- Card-based media selection.
- Large content preview.
- Contextual editing tools.
- Simple creator-oriented editing.
- Contextual panels instead of exposing every tool at once.
- Direct continuation from editing to publishing/scheduling.
- Batch workflow concepts where relevant.
- Mobile Studio as a real creation experience.
- Contextual bottom sheets on Mobile.
- Operational card patterns already used in Mobile history/activity.

## Brand usage posture

Brand green should be disciplined and functional.

Use it for:

- Primary actions.
- Key selected/active states.
- Brand moments.
- Success only where semantic success is intended.

Avoid flooding surfaces with brand green or using it as generic decoration.

## Color direction

Color direction should support:

- Richer light/dark surface hierarchy.
- Clear selected, active, and status states.
- Premium operational clarity.
- Social/content-oriented analytics.
- Restrained domain accents.

Do not introduce glassy gradients, glow, neon, or decorative blobs.

## Typography direction

Typography should follow Vercel Geist-like discipline:

- Clean hierarchy.
- Strong legibility.
- Crisp labels.
- Calm body text.
- Reliable numeric/data reading.
- Precise control text.

Do not use type scale as spectacle.

## Control style direction

Controls should feel precise and highly polished:

- Buttons are clear but not oversized.
- Inputs are quiet and legible.
- Tabs are compact and direct.
- Dropdowns are restrained.
- Focus/hover/active states are clear.
- Excessive pill usage is reduced.
- Excessive radius is reduced.

## Card/list language

Operational data primarily uses modern cards and organized list blocks.

Cards/lists should support:

- Scanning.
- Status.
- Actions.
- Context.
- Lightweight comparison.
- Clear hierarchy.

Tables remain available when comparison, bulk management, or density materially require them.

## Studio layout language

Studio should be creator-first and step-based.

It should not become CapCut Desktop, Premiere, DaVinci, Figma, or a heavy professional editor.

## Mobile visual language

Mobile must support real creation/editing, posting, scheduling, and monitoring.

Mobile should be touch-first, preview-forward, sheet-based when appropriate, and creator-friendly.

## Analytics visual language

Analytics should be social/content-first and action-oriented:

- KPI.
- Trend.
- Chart.
- Top content.
- Recommendation/action.

Analytics should lead to operational action, not just charts.
